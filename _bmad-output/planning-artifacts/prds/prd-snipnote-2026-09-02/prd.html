1. Vision

snipnote is the full-size, fast, local markdown companion for Claude Code terminal lovers. It is not a floating panel (Mote), not a heavy IDE (Cursor 3.0), and not a generic Obsidian replacement — it is the editor you leave open beside Ghostty/iTerm while Claude writes.

Humans edit in a rich WYSIWYG surface (Tiptap) with instant Mermaid/todos/code rendering; Claude reads and writes the same raw Markdown files on disk. The app's job is to never corrupt that shared file, to render what Claude wrote faithfully, and to let the user navigate a local vault in milliseconds — sidebar, Cmd+P, tabs — without context loss.

Why now: Claude Code moved agentic coding to the terminal. Output (plan.md, spec.md, tasks, Mermaid) is Markdown, but the terminal can't render it and Obsidian is too heavy/generic for side-by-side. Mote proved solo-dev floating markdown at $19 can sell; snipnote bets a full-size, cross-platform Tauri editor optimized for the human-agent file handoff earns the first $5 and grows to $19+ as Canvas/Terminal/Floating land incrementally.

2. Target User

2.1 Jobs To Be Done

  • Keep the Claude file open without leaving the terminal workflow. As a Claude Code user who lives in Ghostty/Terminal, I want my plan.md / Tech Stack Decisions open in a fast full-size pane that stays in sync with Claude's writes, so I don't context-switch to Obsidian/VS Code.
    [ASSUMPTION: User uses Claude Code at least weekly and already keeps a local folder of Markdown specs.]
  • Navigate a vault at keyboard speed. I want Cmd+P and file tree to jump between 50–200 Markdown files without lag.
  • Trust the file. Raw Markdown on disk stays pure so I can git diff without injected HTML or mangled frontmatter.
  • Feel in control, not replaced. Local-first, no cloud account — Claude's work is reviewable, not hidden.
  • Build in public with a tool I use myself. Ship a shippable surface in 2–4 weeks, dogfood daily beside Claude, earn first dollar credibly.

2.2 Non-Users (v1)

  • Teams needing real-time collaboration or cloud sync — v1 local-only single-user
  • Mobile users — desktop only
  • Generic note users who never use terminal/AI — better served by Obsidian/Bear/Typora
  • Floating-only capture users — better served by Mote

4. Features

4.1 Vault & File Management — Realizes UJ-1, UJ-2

Local-first vault as file-system mirror. Pick folder on first launch, persist, restore. Sidebar shows File Tree with expand/collapse and Active File Highlight.

FR-1 Open local Vault — Realizes UJ-1

User can pick a local folder as Vault via system dialog. App persists and restores on relaunch. [ASSUMPTION: Tauri dialog plugin; single vault.]

Consequences:
• After picking ~/snipnote-vault, relaunch restores same path without re-prompt.
• Invalid/missing folder shows error and re-prompts; app does not create vault silently.

FR-2 Render File Tree 1:1 — Realizes UJ-1

System displays File Tree in Sidebar matching file system: folders and .md only, sorted alphabetically.

Consequences:
• Shows Daily Notes/, Projects/, Website Redesign/ and Tech Stack Decisions.md exactly as on disk.
• External rename/move (including by Claude) reflected within 2s via watcher.

FR-3 Active File Highlight and Library footer — Realizes UJ-1

System highlights currently open Note in File Tree and exposes Library entry in Sidebar footer.

Consequences:
• Only one Note highlighted at a time; highlight follows Tab/File Tree.
Ready for Obsidian-compatible folder structure — plain .md, frontmatter preserved as text even if not rendered in v1.

4.2 Quick Navigation & Search — Realizes UJ-1 (step 3), UJ-2

FR-4 Search via Cmd+P (filename-only) — Realizes UJ-1

User can press Cmd+P (Ctrl+P on Win/Linux [ASSUMPTION]) to focus Search, type substring, see filtered Note filenames, and jump.

Consequences:
• Typing tech → Tech Stack Decisions.md; access → Accessibility Audit.md.
• Filename-only in v1; no full-text.

FR-5 Navigate via File Tree and Tab selection — Realizes UJ-1, UJ-2

User can click a Note in File Tree or its Tab to make it active, with highlight and Tab Bar update.

Consequences:
• Clicking a Note opens it in Editor and highlights it; Tab Bar shows its name.
• Back/forward arrows navigate tab history within session. [ASSUMPTION: session history only.]

4.3 Editor Core (Tiptap, Markdown Source) — Realizes UJ-1, UJ-2

Full-size Editor with live WYSIWYG rendering but raw Markdown on disk. Parses MarkdownSource to Tiptap on open, serializes back on save. v1 covers headings, bold, links, bullets from your screenshot + Mermaid/tasks/code as rendered [ASSUMPTION].

FR-6 Live Markdown rendering — Realizes UJ-1, UJ-2

Editor renders headings, bold, links, bullets live as user types, no split preview pane.

Consequences:
• # Heading → heading; **bold** → bold; [text](url) → clickable link; - item → bullet.

FR-7 Raw Markdown round-trip fidelity — Realizes UJ-1

System preserves Markdown Source exactly as CommonMark/GFM, no injected HTML. Frontmatter preserved verbatim. [ASSUMPTION: CommonMark + GFM.]

Consequences:
• Opening a file written by Claude and saving without edits → byte-identical (except line endings).
• **x** not rewritten as __x__.

FR-8 File-watcher with external-change handling — Realizes UJ-1

System watches Markdown Source; when Claude overwrites a Note, Editor handles without silent loss.

Consequences:
• If not dirty → auto-reload, preserve scroll/cursor.
• If dirty → banner “File changed on disk — Reload / Keep mine”, never auto-overwrite. [ASSUMPTION: Banner; merge is v2.]

Out of Scope: Three-way merge, conflict files.

Feature NFR: ≥50 fixtures (headings, lists, links, code, frontmatter, Mermaid) must pass byte-equality round-trip tests.

4.4 Tabs & Breadcrumb Navigation

FR-9 Tab lifecycle — Realizes UJ-1, UJ-2

User can see active Note name in Tab Bar, navigate history via arrows, create new Note via +.

Consequences:
• + creates Untitled.md / Untitled 2.md in current folder (or Vault root) and opens it, added to File Tree immediately. Created on disk immediately, not only on save. [ASSUMPTION: immediate create.]
• Close restores prior tabs/vault on next launch via persisted session.

4.5 Status Bar & Document Insights

FR-10 Live document statistics — Realizes UJ-1

System shows live word count, character count, paragraph count in Status Bar, updating on every keystroke and file load.

Consequences:
• For Tech Stack Decisions example: 174 words | 1,209 characters | 10 paragraphs (paragraph = blank-line block [ASSUMPTION]).

4.6 Window & System Integration

FR-11 Native window controls and persistence — Realizes UJ-1, UJ-2

System shows standard macOS traffic lights and persists window size/position across relaunch. [ASSUMPTION: min 800×600.]

Consequences:
• Close/minimize per OS; relaunch restores prior size/position and vault.

5. Non-Goals (Explicit)

  • Not a floating capture panel in v1 (Mote owns this; deferred to v5)
  • Not a Canvas/whiteboard — Excalidraw is v3
  • Not an embedded terminal/PTY running Claude — v4; Claude stays in Ghostty/iTerm beside editor
  • Not cloud sync, collaboration, or accounts — local-only. Ready for future sync (file abstraction) but no sync logic in v1
  • Not mobile, not web — desktop Tauri only
  • Not a full IDE — no LSP/debugger/git UI
  • Not a generic “second Obsidian” — must win on Claude side-by-side sync

6. MVP Scope

6.1 In Scope

  • Vault pick/restore (FR-1), File Tree 1:1 (FR-2), Highlight+Library (FR-3)
  • Cmd+P filename search (FR-4), File Tree/Tab nav (FR-5)
  • Tiptap live headings/bold/links/bullets + Mermaid/tasks rendered (FR-6), raw Markdown round-trip (FR-7), file-watcher banner (FR-8)
  • Tab Bar with + (FR-9), Status Bar (FR-10), native window (FR-11)
  • Plain .md files, frontmatter preserved, vault = file system

6.2 Out of Scope for MVP

  • Canvas/Excalidraw → v3 — major scope, not needed for first dollar
  • Embedded Terminal → v4 — PTY complexity; users keep Ghostty
  • Floating window → v5 — head-on vs Mote, needs multi-window sync
  • Cloud sync / collaboration / accounts — local-first wedge
  • Full-text search, tags, graph, plugins — deferred
  • Obsidian full compat (wikilinks/canvas) — v2 preserves frontmatter only
  • Mobile/web/Linux QA [ASSUMPTION: macOS first, Win/Linux toggle ready but not QA’d]

Adapt-In

Platform

Desktop Tauri v2, React 19, Vite. Primary macOS 13+ [ASSUMPTION]; Win/Linux via targets: all in src-tauri/tauri.conf.json:24 but QA scope per Open Question 5. No mobile/web. Auto-update deferred.

Monetization

Paid one-time, price ladder: v1 $5 → +Canvas $9 → +Terminal $19 — lifetime updates for early tier [ASSUMPTION]. No subscription in v1. Via Lemon Squeezy/Gumroad/Stripe. Free trial: 7-day or 7-note limit [ASSUMPTION]; no accounts in app, license key file.

Information Architecture

Single full-size window. Left: Sidebar (top Search Cmd+P, middle File Tree, bottom Library). Right: Tab Bar (arrows, active name, +) over Editor over Status Bar. No floating panel in v1.

Aesthetic and Tone

References: Obsidian/Typora cleanliness, not Notion heaviness. Anti-reference: IDE chrome. Tone: calm, local, fast. Native traffic lights, neutral typography, live rendering without preview toggle.

Cross-Cutting NFRs

  • Performance: Cold launch <1.5s on M1, file open <200ms for <100KB md, search filter <100ms for 500 files [ASSUMPTION]
  • Reliability: Never silently overwrite Markdown Source. Crash must not corrupt file (atomic write temp+rename)
  • Privacy/Security: No network calls, no telemetry without opt-in, no cloud. Files never leave disk. Harden tauri.conf.json:21 csp: null before launch
  • Accessibility: Keyboard-navigable Sidebar/File Tree, Cmd+P, Tab traversal [ASSUMPTION: WCAG AA deferred but keyboard path required]
  • Observability: File-watcher errors surfaced as banner, not silent
